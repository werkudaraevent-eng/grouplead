1. Platform boundary

Data ownership dan batas antar-app

flowchart LR U[Shared Identity] --> L[LeadEngine] U --> S[Sales Mission] L -->|Users, tenant membership| S L -->|Company/contact API v1| S S --> SDB[(Sales Mission DB)] L --> LDB[(LeadEngine DB)] S -. no direct DB access .-> LDB

LeadEngine master

User, tenant membership, client_companies, dan contacts.

Sales Mission owner

Schedule, assignment, result, notes, attachment, dan reporting mission.

Boundary

Sales Mission hanya memakai API versioned. Tidak membaca database LeadEngine langsung.

2. End-to-end mission flow

Alur dari kontak client sampai reporting

flowchart TD A[Sales/Admin contacts client] --> B{Client confirms visit?} B -- No --> X[Follow-up later] B -- Yes --> C[Create mission] C --> D[Live search company in LeadEngine] D --> E{Company found?} E -- Yes --> F[Save ID + company snapshot] E -- No --> G[Create pending company via API] G --> H[Save pending ID + snapshot] F --> I[Contact optional] H --> I I --> J[Set type, date, time, location, initial contact] J --> K[Assign primary sales] K --> L[Assign supporting sales] L --> M{Conflict after buffer check?} M -- Yes --> N[Change time or assignment] N --> M M -- No --> O[Send notifications] O --> P{Primary accepts?} P -- No --> Q[Admin reassigns, reschedules, or cancels] P -- Yes --> R[Mission accepted] R --> T[Mission appears in calendar and list] T --> V[Mission visit] V --> W[Primary fills result; supporting adds notes] W --> Y[Primary submits result] Y --> Z[Result enters KPI/reporting]

3. Assignment and reschedule

Primary controls confirmation; admin controls schedule

stateDiagram-v2 [*] --> ASSIGNED ASSIGNED --> ACCEPTED: Primary accepts ASSIGNED --> REJECTED: Sales rejects assignment ASSIGNED --> RESCHEDULE_REQUESTED: Sales requests new time RESCHEDULE_REQUESTED --> ASSIGNED: Admin rejects request RESCHEDULE_REQUESTED --> SCHEDULED: Admin approves new time SCHEDULED --> ASSIGNED: Admin assigns sales ACCEPTED --> IN_PROGRESS: Mission starts ACCEPTED --> CANCELLED: Admin cancels IN_PROGRESS --> COMPLETED: Visit finished COMPLETED --> [*] REJECTED --> [*] CANCELLED --> [*]

Primary

Wajib Accept. Jika menolak, admin mengambil tindakan.

Supporting

Boleh accept/reject. Status pending/rejected tidak memblokir mission.

Reschedule

Sales mengajukan waktu baru. Admin menyetujui atau menolak.

4. Result form

Validasi required, tanpa approval wajib

flowchart TD A[DRAFT result] --> B{Required validation passes?} B -- No --> C[Show errors; remain DRAFT] B -- Yes --> D[SUBMITTED] D --> E[Immediately enters KPI/reporting] E --> F{Admin finds specific issue?} F -- No --> G[Keep SUBMITTED] F -- Yes --> H[NEEDS_CLARIFICATION + concrete note] H --> I[Primary updates result] I --> J[SUBMITTED again] J --> E

Supporting note

Catatan terpisah, author dan timestamp tersimpan.

Multiple contact

Form memakai repeatable group: satu mission dapat banyak contact.

KPI

Submission valid langsung masuk reporting. NEEDS_CLARIFICATION hanya flag.

5. Company and contact mapping

Live search, snapshot, review, mapping

flowchart TD A[Add company/contact] --> B{Existing record selected?} B -- Yes --> C[Save master ID + snapshot] B -- No --> D[Save pending snapshot] D --> E{Enough identity data?} E -- No --> F[PENDING_REVIEW; no name-only match] E -- Yes --> G[Send to LeadEngine review] G --> H{Admin CRM decision} H -- MATCH_EXISTING --> I[Map pending to master ID] H -- CREATE_NEW --> J[Create master record] H -- Needs more data --> F C --> K[Mission linked] I --> K J --> K F --> K

6. Tenant switch

Access scope mengikuti LeadEngine

flowchart LR A[User login] --> B[Load allowed tenants] B --> C[Select active tenant] C --> D[Server validates membership] D --> E[Scoped queries use company_id] E --> F[Calendar, list, form, reports] D -. invalid .-> G[403 / no data]

company_id

Tenant/internal business unit pemilik data Sales Mission.

client_company_id

Customer company yang dikunjungi. Bukan tenant scope.

Security

Client tidak boleh menentukan akses hanya lewat tenant ID dari request.
